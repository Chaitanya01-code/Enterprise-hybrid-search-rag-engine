End-to-End Request Flow
1
User visits frontend
React SPA loads at localhost:5173. On mount, checkBackendHealth() pings GET / on the backend. Auth state is restored from localStorage via UserContext.
2
Signup / Login
Credentials are POSTed to POST /signup or POST /login. Backend checks uniqueness (signup) or password hash (login) against PostgreSQL. On success, the user object { id, username, email, role } is saved to UserContext + localStorage.
3
Role-based routing
AdminRoute guard: only role === "admin" reaches /admin. UserRoute guard: role "user" reaches /user; admins are redirected away. Unauthenticated users are redirected to /login.
4
Admin — Document Upload
Admin selects a file in UploadPanel. POST /admin/upload is called with X-User-Role: admin header, file bytes (multipart), optional description and tags. Backend saves the file to uploads/ with a UUID name, persists metadata to documents table, then returns the document record immediately.
require_admin
5
RAG Ingestion Pipeline (background task)
After the HTTP response is sent, a BackgroundTask runs _run_rag_pipeline():

a. Text Extraction — build_chunks() dispatches to extract_text_from_pdf (pypdf), extract_text_from_docx (python-docx), or plain-text decoder based on MIME type / extension.

b. Token Chunking — chunk_pages() splits text into 700-token windows with 100-token overlap (step = 600 tokens). Each chunk records its zero-based chunk_index and source page_number.

c. Embedding — embed_texts() calls models/text-embedding-004 with task type RETRIEVAL_DOCUMENT. Produces a 768-dim float vector per chunk.

d. Persistence — save_chunks_with_embeddings() bulk-inserts DocumentChunk rows into PostgreSQL (embedding stored as JSON text). If embedding fails, chunks are saved without vectors so text search still works.
6
User — RAG Query
User types a question in ChatPanel. Frontend POSTs to POST /query with X-User-Role: user and { question, top_k: 5, document_id? }.
7
Semantic Search (cosine similarity)
semantic_search() embeds the question with task type RETRIEVAL_QUERY. Then iterates all document_chunks rows that have a stored embedding, computes cosine similarity in pure Python (no numpy), sorts descending and returns the top-k chunks (default 5).
8
Gemini LLM Answer Generation
_build_prompt() assembles the retrieved chunks into a numbered context block. _gemini_answer() calls gemini-1.5-flash with an enterprise prompt that instructs the model to answer only from the provided context. The response text is returned directly.
9
Response rendered in chat UI
Backend returns { answer, sources: [{ chunk_name, page_number, chunk_index, score }], chunks_found }. ChatPanel displays the AI answer and collapsible source citations (file name, page, similarity score).

Frontend Pages & Components
Public / Auth
  • Welcome — landing page + backend status
  • Login — username or email login
  • Signup — register with role selection
  • Navbar — shown on public routes only
Admin Dashboard /admin
  • UploadPanel — drag/drop or pick file
  • DocRow — edit / delete / download per doc
  • ChatPanel — RAG query interface
  • AnalysisPanel — stats & charts
  • EditModal / ConfirmModal — inline edit/delete
User Chat Page /user
  • ChatPanel — question → AI answer + sources
  • AnalysisPanel — read-only doc insights
  • Optional: scope search to a single document
State & Theming
  • UserContext — global auth state
  • ThemeContext — dark / light toggle
  • Persisted in localStorage
  • AdminRoute / UserRoute guards in App.jsx
Authentication & Security Model
Password Hashing
  • Primary: bcrypt (salt per user)
  • Fallback: PBKDF2-SHA256 (100 000 rounds)
  • Hashes stored in DB; plaintext never stored
Role Enforcement
  • Backend: X-User-Role request header
  • require_admin — rejects non-admin at 403
  • require_user — rejects unauthenticated at 403
  • Frontend: route guards in App.jsx
How to Run
Backend — port 8000
  • Set DATABASE_URL + GEMINI_API in .env
  • pip install -r requirements.txt
  • uvicorn app.main:app --reload --port 8000 (run from backend/)
  • Tables auto-created on startup via Base.metadata.create_all
Frontend — port 5173
  • npm install (from frontend/)
  • npm run dev
  • API base URL hardcoded to http://localhost:8000 in api.js
  • Production build: npm run build → dist/
